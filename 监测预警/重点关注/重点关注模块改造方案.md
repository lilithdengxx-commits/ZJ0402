# 重点关注模块监测逻辑改造方案

## 背景

重点关注模块分为两类内容：

- **关键人物/关键部门**：针对用户常态化关注目标进行舆情监测，由系统自动算法推荐，无需用户配置监测方案。
- **我的关注**：用户自行配置监测方案（即当前模块逻辑）。

---

## 方案 A：左侧面板分组（最小改动，推荐）

在左侧面板内做**两段式分组**，保留单一"重点关注"主入口，不改动右侧筛选/信息流结构。

```
监测方案（左面板）
├─ 🔥 智能推荐  （系统推荐 · 不可编辑）
│   ├─ 关键人物
│   ├─ 关键部门
│   ├─ 特首
│   └─ 三司十五局
└─ ⭐ 我的关注          （+ 新建 / 🗑 删除）
    ├─ 敏感账号
    └─ ...用户自建方案
```

### 关键交互差异

- **系统推荐分组**：每项前加 `AI` 徽标，hover 不显示删除按钮，无"新建"按钮。
- **我的关注分组**：保留 ＋ 新建、🗑 删除、"预警设置"等全部能力。
- 右侧 filter-zone 共用，但当处于"系统推荐"项时，顶部副标题显示说明：`系统根据您的角色，自动监测以下对象`。

### 优缺点

| | |
|---|---|
| **优点** | 视觉成本最低，用户无需重新学习路径；信息流逻辑零改动 |
| **缺点** | 两类对象语义差异不够显著，用户可能误以为推荐项可编辑 |

---

## 方案 B：顶部主 Tab 三分

把当前 `监测方案 | AI监测报告` 顶部 Tab 扩为三个：

```
[关键人物/关键部门]   [我的关注]   [AI监测报告]
   （系统推荐）       （自建方案）
```

### 各 Tab 说明

- **关键人物/关键部门** Tab：左侧面板变为"系统推荐对象列表"（不可增删），点击查看对应信息流；可加"推荐理由"折叠区（基于角色/历史/热度）。
- **我的关注** Tab：完全保留当前左侧"监测方案"+ ＋ 新建 / 🗑 删除 的逻辑。
- **AI监测报告** Tab：保持不变。

### 优缺点

| | |
|---|---|
| **优点** | 路径分明，两类业务逻辑物理隔离，未来扩展互不干扰 |
| **缺点** | 顶部 Tab 略拥挤；用户在两类对象间切换成本上升一层 |

---

## 方案 C：左侧面板顶部 Segment 切换 + 同区复用

左侧面板顶端加一个 segmented control，切换"系统推荐 / 我的关注"，下方列表随之刷新；右侧内容区不变。

```
┌─────────────────────────┐
│ [系统推荐] [我的关注]   │   ← segmented
│─────────────────────────│
│ 🔥 关键人物              │
│ 🔥 关键部门              │
│ 🔥 特首                  │
│ ...                      │
└─────────────────────────┘
```

### 关键交互差异

- 切到"我的关注"时，面板头部出现 `＋ 新建方案` 按钮和搜索；切到"系统推荐"时按钮隐藏，仅保留搜索与"刷新推荐"。
- 右侧 filter-zone 共用，但"预警设置"按钮仅在"我的关注"下显示；"系统推荐"下改为 `订阅日报 / 周报`。

### 优缺点

| | |
|---|---|
| **优点** | 横向空间利用率高，保留主 Tab 给"监测方案 vs AI报告"语义；推荐与自建在视觉上完全独立 |
| **缺点** | 需要新增 segmented 组件并维护切换状态 |

---

## 方案 D：左侧二级导航树（重构最彻底）

把左侧面板改成两级折叠树，把"系统推荐"做成可展开的智能目录。

```
▾ 系统推荐（AI）
    ├─ 关键人物
    │    ├─ 行政长官
    │    └─ 司局长
    └─ 关键部门
         ├─ 行政会议
         └─ 三司十五局
▾ 我的关注
    ├─ 敏感账号
    └─ ＋ 新建方案
```

### 关键交互差异

- **系统推荐节点**：前面加 `AI` 徽标，hover 不显示删除按钮，无"新建"按钮。
- **我的关注节点**：保留全部 CRUD 能力，可编辑、删除、拖拽排序、分文件夹。
- 右侧 filter-zone 共用，但当处于"系统推荐"项时，顶部副标题显示说明：`系统根据您的角色，自动监测以下对象`。

### 优缺点

| | |
|---|---|
| **优点** | 信息架构最完整、可扩展性最强，适合后续接入更多算法标签与个性化推荐 |
| **缺点** | 改动面最大（左侧组件、状态管理都要动） |

---

## 方案对比总结

| 维度 | A 分组 | B 主Tab三分 | C Segment切换 | D 树形导航 |
|---|:---:|:---:|:---:|:---:|
| 改动量 | 极小 | 小 | 中 | 大 |
| 两类逻辑隔离度 | 弱 | 强 | 中 | 强 |
| 视觉清晰度 | 中 | 强 | 强 | 强 |
| 后续扩展性 | 弱 | 中 | 中 | 强 |
| 用户学习成本 | 低 | 低 | 低 | 中 |

## 选型建议

- **追求快速上线/验证** → 选 **方案 A**
- **业务上认为两类是平行场景、需要清晰心智模型** → 选 **方案 B**（最贴合"分为两类内容"的表述）
- **想兼顾空间与清晰度** → 选 **方案 C**
- **未来要做精细化推荐目录树** → 选 **方案 D**
